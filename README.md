# Barlih

Приватний котедж із банею та терасами в Карпатах. Джерело вимог — `docs/TZ.md`.

## Поточний етап

**Крок 0 — каркас.** Реалізовано базові стилі, конфігурацію, три мовні сторінки з одного шаблону, основу i18n, шар доступу до даних і пакування статичних файлів. Повна верстка секцій починається на Кроці 1. Каркас не готовий до публікації; HTML має `noindex, nofollow`.

## Запуск

Потрібні Node.js ≥ 18 та Python 3 для локального сервера. Залежностей npm немає; `npm install` не потрібен.

```sh
npm run build
npm start
```

Відкрити `http://127.0.0.1:8080/`, `/en/` або `/pl/`. Сервер запускається з кореня проєкту. Альтернативи:

```sh
python -m http.server 8080 --bind 127.0.0.1
# Якщо Python доступний під назвою python3:
python3 -m http.server 8080 --bind 127.0.0.1
```

Не відкривати сайт через `file://`: ES-модулі потребують HTTP. `Ctrl+C` зупиняє локальний сервер.

## Команди

| Команда | Призначення |
| --- | --- |
| `npm run build` | Генерує `/index.html`, `/en/index.html`, `/pl/index.html`, `sitemap.xml` |
| `npm run build:pseudo` | Генерує текст приблизно на 40% довший із діакритикою; потім відновити звичайним `build` |
| `npm run build:prod` | Перевіряє ключі й відхиляє `TODO-OWNER`, `NEEDS-REVIEW`, `LEGAL-REVIEW`; зараз відмова очікувана |
| `npm test` | Тести збірки, екранування, локалізації, пакування та меж незавершених адаптерів через `node --test` |
| `npm run build:availability` | Каркас CLI: завершується з явною помилкою без запису файлів; реалізація на Кроці 4 |
| `npm run package` | Збирає сторінки та створює пакет розробки `dist/` за білим списком |
| `npm run package -- --prod` | Пакет із забороною невирішених позначок; зараз відмова очікувана |

Мінімізація HTML/CSS/JS під час `package` запланована **лише на Кроці 7** відповідно до оновленого ТЗ.

## Структура та джерела істини

```text
templates/index.template.html       розмітка каркаса
locales/{uk,en,pl}.json             тексти та ui; однакові змістові ключі
locales/{GLOSSARY,STATUS}.md        терміни й стан перекладів
styles/base/                       tokens → reset → typography → layout → utilities
scripts/config.js                  єдині налаштування, ціни, контакти, правила
scripts/core/i18n.js                t(key, params), plural(key, n, params)
scripts/api/dataSource.js           getSettings/getBlockedRanges/getReviews/submitBookingRequest
scripts/data/                      явно позначені DEMO; не підключені до інтерфейсу
data/availability.json             не налаштовано: generatedAt = null
assets/                            локальні SVG-плейсхолдери, маніфест джерел, опис шрифтів
tools/                             збірка, пакування, каркас конвертера ICS
tests/                             тести без залежностей
index.html, en/, pl/, sitemap.xml  згенеровані файли; зберігати разом із вихідними
dist/                              згенерований пакет; не зберігати у Git
```

Згенерований HTML вручну не редагувати. Після зміни шаблону, конфігу чи мов виконати `npm run build`. Немає порожніх файлів для майбутніх секцій; вони додаються на своєму кроці.

## Мови

Українська — `/`, англійська — `/en/`, польська — `/pl/`. Автоматичних редиректів немає. Весь видимий текст і доступні назви — з `locales/`. У браузерний JSON-пакет потрапляє тільки `ui`; сторінки та JSON-LD статичні й читаються без JS.

`t('currency')` читає ключ із `ui`; `plural('nights', 3)` застосовує `Intl.PluralRules`. Мова береться з `<html lang>`. uk/pl мають `one/few/many/other`, en — `one/other`. Усі нові змістові ключі додаються до трьох JSON одночасно; відсутні/зайві ключі та несумісні типи зупиняють збірку. en/pl — чернетки `NEEDS-REVIEW`; повна локалізація й перевірка носіями — Крок 6.

## Дані та чесні стани

`CONFIG.flags.showDemoData = true` дозволяє лише явно названі демонстраційні дані. Демо-діапазони генеруються від поточного дня в `Europe/Kyiv`, не є реальними бронюваннями й поки не відображаються. Вигаданих відгуків немає; список порожній. У проді прапорець має бути `false`.

Порожній `availability.json` із `generatedAt: null` означає **календар не налаштований**, а не «всі дати вільні». Реальна доступність і її перевірки — Крок 4. `submitBookingRequest` до Кроку 5 відхиляє запит з `BOOKING_SUBMISSION_NOT_IMPLEMENTED`; не імітує відправку.

Приватний `.ics` у майбутньому зберігати лише в `data/calendar/`; не комітити й не деплоїти. У `dist/` потрапляють тільки публічні файли; `.ics`, `.env*`, Markdown і службові каталоги виключені. Деталі — `DEPLOY.md`.
